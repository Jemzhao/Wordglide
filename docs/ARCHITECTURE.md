# 项目结构与主要流程

Wordglide 是一个使用 SwiftUI、AppKit 和 Apple Translation 的 macOS 应用。项目由 Swift Package Manager 管理，保留一个可执行目标 `Wordglide` 和一个测试目标 `WordglideTests`。以下子目录用于组织职责，不是独立模块；目录之间仍在同一模块内协作。

## 目录职责

| 目录 | 主要内容 |
| --- | --- |
| `Sources/Wordglide/App/` | `App.swift` 负责生命周期、菜单栏、窗口、面板和全局快捷键接线；`Model.swift` 保存界面状态、翻译请求和恢复结果。 |
| `Sources/Wordglide/UI/` | 主窗口、设置页、翻译卡片、快捷替换提示、共享样式和透明面板容器。 |
| `Sources/Wordglide/Translation/` | 翻译服务协议、系统语言包检查、本机翻译、缓存、取消和超时处理。 |
| `Sources/Wordglide/Capture/` | 辅助功能取词、选区读取、Vision OCR，以及悬停、选区和输入事件监听。 |
| `Sources/Wordglide/Replacement/` | 快捷替换协调、编辑器和选区校验、输入法组词检测、一次粘贴事务、快捷键设置及内存中的恢复结果。 |
| `Sources/Wordglide/Updates/` | 公共更新配置校验、更新状态及 Sparkle 标准更新流程的适配；未配置更新源时不启动。 |
| `Sources/Wordglide/Shared/` | 文字清理、语言判断、UTF-16 选区处理、卡片布局和屏幕坐标计算。 |
| `Sources/Wordglide/Development/` | 命令行诊断、核心检查、窗口／替换集成检查和界面预览导出工具。仍编译进当前可执行目标，由显式诊断参数触发。 |
| `Tests/WordglideTests/` | 按 `App`、`Capture`、`Translation`、`Replacement`、`Shared`、`Updates` 分组的回归测试。文件位置与源代码职责对应，测试目标名称不变。 |
| `scripts/` | 本地构建、运行、测试、签名配置、DMG 打包及 Sparkle 更新发布准备。 |
| `ThirdParty/` | 保留的第三方许可证；来源说明见根目录的 `THIRD_PARTY_NOTICES.md`。 |

图标素材位于 `Assets/`，应用打包信息位于根目录的 `Info.plist`；构建脚本将资源复制进应用包。实际使用要求、构建步骤和许可信息以 [README](../README.md) 为入口。

## 翻译流程

1. `HoverMonitor` 接收悬停、选区和快捷键事件，通过 `TextCapture` 读取辅助功能文字；允许 OCR 的悬停路径可使用屏幕截图和 Vision 识别。
2. `AppModel` 管理来源文字、语言方向和翻译卡片状态，调用 `TranslationService`。
3. `LocalTranslator` 检查中英文语言包并调用 Apple Translation。请求有 30 秒期限，支持取消；失效请求的迟到结果不会更新当前界面。
4. 结果交给 SwiftUI 视图展示。`AppDelegate` 配合 `ScreenGeometry` 管理浮窗的位置、尺寸和显示器变化。

手工输入和剪贴板翻译也复用模型与翻译服务，不需要走悬停采集流程。

## 快捷替换流程

`DirectReplacementCoordinator` 管理快捷替换的读取、翻译、再次校验和提交过程。`ReplacementTarget` 保存目标编辑器及原选区信息；`TextReplacement` 在真正粘贴前重新确认原应用、焦点、文字和选区。

替换使用一次普通粘贴，让接收应用处理其原生编辑和撤销行为。`ReplacementAttempt` 是共享的提交门闩：继续输入、点击、切换应用等会使等待中的请求失效；已经发出的粘贴继续确认结果，不能因无法确认而再次发送。输入法组词、多个选区和待替换范围内的附件均有相应保护。

临时剪贴板在事务结束时尝试恢复原内容，并避免覆盖事务期间用户新写入的剪贴板内容。不同编辑器的辅助功能实现及撤销行为仍需实机验证，单元测试不能代替应用兼容性测试。

## 失败恢复

`ReplacementRecovery` 只保留在内存中，包含本次原文、目标语言、可用译文和提示信息，不持有可重放的目标编辑器或粘贴权限。`AppModel` 负责展示、复制和清除恢复结果。

翻译超时可以手动重试。恢复入口只生成或复制译文，不自动再次替换原输入框，从而避免旧选区被重放。成功替换、失败和结果不确定是不同状态，应在修改流程时保留这种区别。

## 应用内更新

`AppUpdater` 管理更新状态、自动检查偏好及安装等待，`SparkleUpdateClient` 使用 Sparkle 的标准界面、下载验证与安装器。公钥和 HTTPS 更新源由打包时的公开配置写入应用；私钥只由维护者发布工具从钥匙串使用，不进入应用包。测试注入客户端，不访问网络或真正安装。

发现新版本后菜单栏提供提示。翻译、替换、剪贴板恢复或语言包准备进行时延后安装；已提交的替换按实际事务完成情况计数，不以弹窗是否关闭作为判断。更新服务不接收翻译文本或截图，关闭系统信息上报。配置和发布流程见 [应用内更新](UPDATES.md)。

## 修改时的边界

- 窗口和可观察界面状态主要在 `@MainActor` 上更新。辅助功能读取和 OCR 使用各自的异步工作路径；不要把同步的外部应用读取搬到界面更新路径上。
- 使用 `ScreenGeometry` 和既有坐标转换函数处理 Cocoa／Quartz 坐标，不假定屏幕原点为零或所有显示器尺寸、缩放相同。
- 文本选区使用 UTF-16 范围，处理 emoji 和组合字符时应沿用 `SelectionEdit` 及内容策略校验。
- 不通过直接写回整个输入框来绕过替换校验，也不自动重试粘贴。新增回退应继续保留一次提交限制与用户明确操作。
- 新的可复用逻辑按职责放入现有目录。仅为分类无需新增 SwiftPM 目标；有明确的依赖或复用需求时再拆模块。
- 移动、修改参考上游实现的文件时保留现有版权注释，并同步维护第三方来源与许可说明。

## 验证方式

运行 `./scripts/test.sh` 执行回归测试与核心自检；运行 `./scripts/build-app.sh` 验证应用打包和签名。涉及窗口、输入法、剪贴板或跨应用替换的修改，还需要在明确的测试样例中做实机检查。开发诊断参数和更详细的验证记录见项目文档；自动化通过不代表所有输入法、编辑器和多屏硬件已经覆盖。
